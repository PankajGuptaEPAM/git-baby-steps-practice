# How to Fill Out the Weekly Status Report

Use `template.md` as your starting point. Copy it, rename it with the date (e.g. `report-2026-08-21.md`), and fill in each section as described below.

---

## Header Fields

| Field | What to write |
|-------|--------------|
| **Project** | Full project name (e.g. Diamond Marketplace) |
| **Sprint / Period** | Sprint number or date range (e.g. Sprint 24 / Aug 18–22) |
| **Date** | Today's date in YYYY-MM-DD format |
| **Prepared By** | Your full name |

---

## Overall Status

Choose one colour per dimension:

- 🟢 **On Track** — no issues, progressing as planned
- 🟡 **At Risk** — potential issue, monitoring closely
- 🔴 **Off Track** — action required immediately

Add a short note in the Notes column explaining _why_ if the status is 🟡 or 🔴.

---

## Completed This Week

List every task, ticket, or milestone finished this week. One bullet per item.  
Include the Jira ticket ID if applicable (e.g. `[PROJ-123] Deployed auth service`).  
Do not list items that are still in progress.

---

## In Progress

Fill in the table for everything actively being worked on:

- **Item** — brief description or Jira ticket ID + title
- **Owner** — first name or initials of the responsible person
- **ETA** — expected completion date (MM-DD)

---

## Blockers

List anything preventing progress. If there are none, write `None`.  
For each blocker, state what is blocked and who needs to act to unblock it.

---

## Next Week Goals

List 2–5 concrete outcomes you aim to achieve next week.  
Keep them specific and measurable (e.g. "Complete API integration for search endpoint").

---

## Risks

| Column | What to write |
|--------|--------------|
| **Risk** | Short description of the potential problem |
| **Impact** | High / Medium / Low |
| **Mitigation** | What you are doing (or plan to do) to reduce it |

If there are no risks, delete the table rows and write `None`.
